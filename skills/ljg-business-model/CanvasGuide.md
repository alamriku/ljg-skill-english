# Business Model Canvas: the classification and spatial contract

Based on the Business Model Canvas by Alexander Osterwalder and Yves Pigneur (Business Model Generation) and the official Strategyzer canvas. What follows is a summary and an adapted layout; it does not claim a page-by-page review of the book.

## The nine blocks

| JSON key | Block | What this block answers | Boundary with its neighbours |
|---|---|---|---|
| customer_segments | Customer segments | Which people or organizations is value created for? Who uses it, who pays? | Avoid "everyone"; write each side of a platform separately |
| value_propositions | Value propositions | In which situation does the customer get what result, and why choose this? | Connect product features to customer outcomes; not slogans |
| channels | Channels | How do customers find, evaluate, buy, receive and get support? | Write the path, not a list of social platforms |
| customer_relationships | Customer relationships | How is the relationship established, maintained and deepened? | Personal service, self-service, community, co-creation |
| revenue_streams | Revenue streams | Who pays for which value, in what unit and on what cycle? | Funding is not revenue; mark one-off versus recurring |
| key_resources | Key resources | Which assets or capabilities are required to deliver the value? | Stocks: premises, equipment, brand, data, people, capital |
| key_activities | Key activities | What must be done continuously to deliver the value? | Describe actions; do not repeat the asset names here |
| key_partners | Key partners | Which outside partners are relied on, and what does each provide? | An ordinary customer is not automatically a partner; include supply relationships only where they matter |
| cost_structure | Cost structure | Which activities and resources consume cost, and what drives it? | Fixed and variable spending; keep the source's amounts and periods |

Customer segments decide who the value proposition is for; channels and relationships put the value into customers' hands; activities, resources and partners carry the delivery; revenue and cost explain how value is captured and what it costs. Check those correspondences - never invent material to make the relations line up.

## Classical layout

```text
+----------+----------+----------+----------+----------+
|          | key      |          | customer |          |
| key      | activit. | value    | relation.| customer |
| partners +----------+ proposi- +----------+ segments |
|          | key      | tions    | channels |          |
|          | resources|          |          |          |
+----------+----------+----+-----+----------+----------+
|      cost structure      |      revenue streams      |
+--------------------------+---------------------------+
```

The header holds the subject, the scope or stage, the date or version, and a one-line summary. Use the task's local time zone for the date. The canvas is landscape by default, and information density comes before preserving a particular aspect ratio. Every status label and source number stays visible; keep the full source notes in the JSON instead of filling the card's footer with raw interview text.
